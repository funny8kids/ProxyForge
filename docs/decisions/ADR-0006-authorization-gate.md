# ADR-0006：授权状态作为硬门槛，三重实现

- 状态：Accepted
- 日期：2026-11-01
- 相关：[SEC-001 §6](../security/01-security-design.md)

## 背景

"免费代理 IP 列表"类产品的最大风险不是技术，而是合规与安全：使用未授权资源、经由不可信代理传输数据。蓝图明确要求"授权状态必须作为硬门槛，未经授权的资源不能通过高质量分数进入正式资源池"。

如果只在一个地方做检查（例如只在 UI 上过滤），任何新入口（脚本、订阅、编译）都可能绕过。

## 决策

授权门槛在**三个独立层次**实现，任一层失效都不至于造成越权使用：

1. **数据层**：视图 `v_schedulable_endpoints` 固定过滤 `authorization_status IN ('AUTHORIZED','RESTRICTED')` + 健康状态。
2. **编译层**：`PolicyCompiler` 只从该视图取数，编译产物中不存在不合格端点。
3. **渲染层**：`SubscriptionRenderer` 同样只从该视图取数。

同时：

- `UNKNOWN` 视为不可用（默认拒绝，而非默认允许）。
- 状态流转受数据库约束保护：`authorization_status='REVOKED'` 时 `lifecycle_status` 必须为 `REVOKED`。
- 来源类型附加限制：`PUBLIC_PROXY` 默认不得进入网关，只能进入 `PUBLIC_EXPERIMENTAL` 池供订阅实验（见 SEC-001 §6.2）。
- 授权变更触发强制重编译（不等定时任务）。

## 后果

**正面**

- 合规风险可控：任何路径都无法使用未授权资源。
- 授权撤销能在一分钟内从配置中消失。

**负面**

- `UNKNOWN` 资源默认不可用，新导入资源需要人工确认授权，增加操作成本。
- 三重实现有冗余，需保持三处逻辑一致（用同一个视图收敛，降低漂移风险）。
- 每次授权变更都触发编译，需去抖。

## 验证

`AuthorizationGateIT`：把端点置为 `UNKNOWN` → 触发重编译 → 断言网关配置与订阅 YAML 中均不包含该端点；再置为 `AUTHORIZED` → 断言恢复。
